# 同一页面的人机协作

新会话默认启用协作，CLI 与 DSH 由同一个扩展控制器强制执行，不依赖 Agent 调用 enable/share。用户可以直接操作页面；扩展及时停止后续 Agent 输入，Agent 读取最新状态后继续完成原任务。普通页面操作只改变环境，不修改任务目标。明确的停止指令仍优先于自动继续。

## 使用

启动会话并打开任务页面，直接同步：

```sh
bsk session start --json
bsk navigate 'https://example.com' --session SID
bsk cooperate sync --session SID
```

`sync` 返回 `context_id`。Agent 将自己实际读到的 ID 通过 `--context ID` 传给一次动作，之后再次同步。ID 是一次性凭证；不能把新 ID 补到旧计划上。

```sh
bsk cooperate sync --session SID
bsk fill @e3 --value Shanghai --session SID --context CONTEXT_ID
bsk cooperate sync --session SID
```

遇到 `cooperation_sync_required`，使用 `cooperate wait` 等待，再 `sync`，根据当前结果重新决定下一步。不能直接重试原动作。`effect_state: unknown` 表示可能已经产生效果，必须检查页面或业务记录，尤其不能盲目重复提交。

DSH 使用 `bsk_session` 的 `sync`、`wait-user`、`cooperation-status`。旧 `share/enable` 入口保留为兼容的同步与任务页绑定操作，无需调用。页面操作显式传 `contextId`。插件不会替 Agent 自动填入最新 ID。

## 用户交互

- 用户保留系统鼠标。Agent 点击处短暂显示目标标记，不移动用户的系统指针。
- 普通点击或滚动后，短暂安静即可继续。按住鼠标、按键、输入法组合和文本编辑期间保持人工控制。
- 暂停控件用于阅读或较长操作；“交给 Agent”结束编辑保持。输入法组合或拖拽尚未结束时，交回不会强行抢走输入。
- 工具条只占自身区域，页面不再铺设输入遮罩。“正在停手”表示旧操作还在收尾；“人工操作中”表示没有 Agent 动作执行。
- 真实人工输入、主动接管或完成求助后的页面在会话结束或连接断开时保留，避免丢失人工编辑；无人介入的 Agent 创建页面仍按原路径关闭。用户把任务页移出任务窗口时交还页面，不再列入会话停止的关闭清单。
- “停止任务”与临时保持人工控制不同：后续动作和协作等待均返回 `user_aborted`，不能自动重新规划后恢复。

- 会话创建时固定初始任务标签页。人工切换或打开别的标签页不会改变默认任务页；需要转到另一任务页时，显式选择标签页，或同步时指定 `--tab-id`。原任务页关闭或移出窗口后，旧上下文失效，默认请求报错，不退回当前激活页。
- 只有人工介入过且仍在协作的页面才保持会话，避免等待人工触发空闲回收。停止协作、关闭或移出最后一个人工参与页后重新计时；显式结束会话、关闭窗口或断开连接仍按既有路径清理。

初始空白页只允许在确认 URL、窗口归属和导航代次均未变化时执行首次导航；发送前仍走原生守卫。用户提前导航后，首次导航也必须让路。无人介入的空白或已打开任务页会话都继续正常空闲回收，观察、DOM 更新和 Agent 输入不会开启保留。

页面采集器安装监听后主动报告就绪，后台验证已有归属并启动采集。因此工具条和人工输入采集不等待 Agent 第一次同步。新增、借用及观察到的任务弹窗复用同一归属与清理机制；不接管用户自行打开的无关页面。DSH 合并启动与导航期间若发生协作让路，保留已创建会话并返回同步提示，不清理用户已完成的进度。

## 实现边界

扩展中的 `cooperation/controller.ts` 是控制权和上下文的唯一权威；`action-guard.ts` 为每次请求建立独立的输入清理记录，并复用现有 `sendGuarded`，在 Chrome 原生发送前做最后一次校验。守卫覆盖准备阶段和原生输入；释放该请求自己按下的按键、鼠标或临时焦点配置仍允许收尾，且绑定原来的调试连接。

上下文绑定标签页、文档、人工介入代次和引用表版本。开始动作时消费上下文，同一页不能并发使用它。人工介入、导航、引用表替换都会使旧动作失效。页面变化时复用现有 VOM 语义节点校验内容，忽略单纯 CSS 类名变化；点击前再次核对位置和实际命中目标。后台通知之外，发送前还主动向每个 frame 读取状态，避免只靠通知造成漏判。

鼠标输入使用视口 CSS 坐标，CDP 的节点命中使用文档 CSS 坐标，二者通过对应 target 的滚动偏移转换，不乘屏幕像素比或浏览器缩放。测量先复用 `getBoxModel` 刷新布局，避免后台 `getContentQuads` 返回旧位置。跨进程 iframe 逐层校验父页面中的 owner，不能将其误判为遮挡，也不能跳过父页面上的真实遮挡。后台 `scroll-to` 复用现有输入准备与清理，不激活标签页。

会话生命周期复用 `session.activity` 事件。Daemon 只接受所属浏览器的状态更新，将协作保持与最后工具调用时间一起保存在既有活动记录中；结束保持后有完整的空闲间隔。释放、断线和 session id 复用均清理这一状态。

默认校验整个已观察页面。Agent 已明确知道决策范围时，可重复传入 `--depends-on @eN`，DSH 对应 `dependsOn`。范围必须包含决策依赖的所有区域；目标所在表单、列表或对话框、全部字段值和模态状态仍会检查。比如选择最低价，不能只声明一个按钮而漏掉其他候选。依赖不明确时保留整页校验。持续刷新且与决策无关的区域可以不阻断动作，但有意义的变化仍要求重新同步和规划。

`cooperation-capture.ts` 在隔离世界采集输入和 DOM 变化。输入保持即时通知，DOM 变更合并后通知；主文档及 iframe 都必须响应。普通字段变化走增量路径，字段以文档内稳定标识区分，同名字段和开放 Shadow DOM 输入框也分别记录。结构变化、文档替换、字段过多或内容截断时，复用现有 VOM 快照刷新基线。增量字段变更同步后会更新内部语义证据，避免后续动作仍拿旧值比较；不重复输出整页文本，不替换引用表。采集不触发 hover。密码、文件选择不进入字段变化流。

原生输入时间在每个 frame 准备接收时，使用当前系统时钟和单调时钟换算到事件时间轴。不能直接把 `performance.timeOrigin` 加回事件时间，与当前 `Date.now()` 比较：浏览器长期运行或系统校时后，两者可能偏移。匹配范围覆盖 Date.now 的毫秒截断及原生 CDP 转换、DOM 时钟的独立精度误差（固定 1.5 毫秒预算），不随渲染等待延长；采样被打断时不扩大范围。跨进程时钟的短暂差异还用 epoch 投影核对，采用同一精度预算，且只在投影与当前校准的精度预算一致时接受；偏离预算的旧起点不能形成另一个匹配窗口。每个预期输入只匹配一次。回归包含真实记录中的 1.3 毫秒偏差、跨进程偏移和 epoch 投影的 0.8 毫秒舍入误差，并验证后续同坐标输入及相差 5 毫秒的人工输入仍会撤销旧动作。

人工操作记录在扩展中保留有界日志，跨导航仍可提供已收到的操作，记录缺口独立报告。当前业务状态足以确定进度时，Agent 应继续完成目标，跳过用户已完成的步骤；不能只因历史不完整要求用户重复协助。共享求助复用既有面板，独立于已失效的动作上下文；导航中的采集暂不可用由等待过程恢复。单个 frame 的空采集响应最多重试一次，仍使用原文档、控制租约和 1,200 毫秒总截止时间；人工交回操作不重试，超时后也不再补发采集。

`cooperate wait/status/sync` 不占用普通动作队列。扩展自身仍防止同步与动作互相覆盖。等待结果由工具返回给 Agent，不把 UI 推送当作模型已读到的信息。

## 验证

确定性用例覆盖默认会话创建、首次导航及设备模拟期间人工介入、通知丢失、并发复用上下文、延迟交回、编辑保持、准备期间结构变化、部分执行后清理、引用表替换和采集失联；新建/借用标签页不启用后台焦点模拟，会话停止取消时继续保留保护。

CLI 与 DSH 真实浏览器验收均不调用 enable/share。DSH 用实际发布工具、进程执行器和会话管理流程连接独立 Daemon，分别验证正常启动、合并启动期间人工先导航、人工误操作后旧动作拒绝，以及重新同步后完成正确的一次提交。

真实浏览器用例位于 `evals/browser/cases/regression/cooperation/`。它运行独立浏览器配置、独立 Daemon 和本地业务服务，使用第二条原生输入通道模拟人工操作。服务端独立记录订单，检查错误提交为零、最终城市和数量正确、每个任务仅提交一次。三个布局种子还覆盖后台填写及返回前台后的人工介入、iframe 输入、工具条保持/交回、文档替换、用户完成部分步骤以及提前完成整个任务。后台用例检查原生光标定位不会误触发人工编辑保持，也不会激活后台标签页。额外覆盖只读选择器、复选框、下拉框、拖动保持、开放 Shadow DOM 焦点交接、持续页面刷新、悬停变化、候选价格变化、目标遮挡及共享求助，每个布局还重复执行 32 次 Agent iframe 点击核对输入归因。隔离采集环境还分别注入 +8.8、−8.8 毫秒及两分钟的 epoch 起点偏移，验证点击、后台填写和 iframe 输入不会制造人工保持，真实人工输入仍可撤销旧动作。它验证控制机制与协议，不证明任意模型在任意网站上的任务成功率。

```sh
BSK_DAEMON_WS_URL=ws://127.0.0.1:52917 pnpm ext:build
cargo build --locked
BSK_COOP_CHROME='/path/to/Chromium' pnpm eval:browser:cooperation
```

新增回归覆盖：滚动后的前台与后台点击、切页后省略 `--tab-id` 的等待/同步/观察和操作；无关前台页面的人工点击不改变任务目标，也不撤销任务页的有效上下文。无关页面放置同名输入框和按钮，独立核对其值、点击次数和可见状态不受 Agent 影响。任务标签页关闭后，等待、同步、观察及旧上下文操作均须失败，不能落到剩余标签页。底层真实浏览器几何测试还覆盖 DPR 1/2、80%/100%/125% 缩放、横纵滚动、嵌套与跨进程 iframe、后台布局变化、目标移动和父页面遮挡。Rust WebSocket 测试验证保持、普通工具调用不清除保持、外部浏览器不能清除保持、释放后回收及 session id 复用。单元测试覆盖任务页关闭后不得误操作当前页，以及多任务页只在最后一个人工参与页结束后释放保持。

命中回归覆盖悬停后出现的 `::before` / `::after`、目标子节点的伪元素及其他元素的伪元素遮挡。CDP 可能把命中结果解析为 `CSSPseudoElement`；校验先取其所属 DOM 元素，再执行既有的后代/Shadow DOM 归属判断，避免对非 Node 对象调用 `contains()`。未知对象仍不通过，跨 frame 校验保持有效。

默认快速用例使用 8 秒空闲阈值并静置 12.5 秒。设置 `BSK_COOP_FULL_IDLE=1` 时，不传入任何空闲阈值覆盖，实际使用默认 5 分钟并连续静置 360.5 秒，留出两个 30 秒回收扫描周期的余量。等待期间不发 CLI 保活调用；同一次测试必须同时证明人工接管会话保留、CLI 与 DSH 的非空无人介入任务被回收且页面和空窗口关闭；还检查显式停止的清理，并在 270 秒确认尚未提前回收，随后继续完成人机协作任务。

新版本 Chrome 可设置 `BSK_COOP_LOAD_CDP=1`，通过 CDP 在独立测试配置中加载扩展，避免混用旧命令行加载开关。
设置 `BSK_COOP_DPR` / `BSK_COOP_ZOOM` 可调整端到端浏览器像素比与缩放。
设置 `BSK_COOP_HEADFUL=1` 可用可见浏览器执行同一组用例。体验服务正在运行时，另选 `BSK_COOP_PORT`，并把测试扩展的 `BSK_DAEMON_WS_URL` 构建到同一端口，避免复用体验中的连接。

## 当前限制

本次体验版本默认开启协作。所有非只读工具进入统一动作守卫，不再用能力白名单拒绝原有工具。用户脚本在原生发送前检查上下文；内部导航就绪探测仍是只读。上传、拖放和下载复用既有事务，文件暂存保留 context_id 和 depends_on。窗口、标签页、全页滚动截图和网络调试在浏览器 API 调用前经过同一控制权检查。普通用户标签页的只读观察，以及已关闭任务的调试历史继续遵循原有权限规则。

导航、刷新和历史跳转会正常废弃旧页面的观察上下文，但不会因此把导航工具已确认的完成回执改成失败。回执不授予继续操作的权限，后续动作仍须重新同步；导航期间的人工输入、暂停、停止和取消仍优先生效。

人工介入会撤销动作的上下文并取消可取消的等待。上传拦截器、私有探测监听器和已按下的输入仍要在原连接上清理；取消不允许补发文件设置、脚本或点击。已发送的异步脚本不能被回滚，未决结果标记 unknown，Agent 必须核对业务状态后选择下一步，不自动重放。

DSH 的 bsk_interact 增加 evaluate、upload 和 download，复用既有会话所有权、队列、取消和观察记录。CLI 既有命令不变。远程连接的文件传输限制等既有约束保持原语义。

已经交给 Chrome 的命令无法撤回。人工输入与 Agent 输入在浏览器中都可能是可信事件，因此通过原生事件时间和具体输入识别 Agent 输入；预期不会因渲染超过 200 毫秒就过期，也不扩大接受人工事件的时间窗口。原生时间用于跨 iframe 坐标系归因。它不构成完整的用户操作审计，也不能证明极近时刻、同一位置的输入来源。检测到变化后，系统保证不继续使用已失效的计划；已产生的外部副作用只能核对或补偿。

增量路径主要面向普通 DOM 表单。封闭 Shadow DOM、纯画布和复杂自定义编辑器仍需要单独验证；页面当前状态与历史操作是否完整分别报告。不能因为刷新了基线就断言历史上没有发生过提交。

## 能力兼容回归

`compatibility.mjs` 使用独立 HTTP 服务核对上传的二进制字节、下载文件内容和实际请求次数。CLI 与 DSH 均验证：无人介入的同步/异步脚本及脚本异常、文件选择上传与拖放上传、下载与已有文件保护；人工操作后的过期上下文不产生副作用；脚本执行中、等待文件选择时、下载过程中插手；保留已确认下载的凭据、重新观察、纠正字段，并验证请求不重复。另验证窗口调整、页面加载后的设备模拟、主动悬停观察、全页截图及显式关闭标签页。

`BSK_COOP_COMPAT_ONLY=1` 只运行兼容用例；默认运行同时包含原有通用协作、DSH 启动插手、标签页切换和空闲回收用例。单元测试另在异步准备与原生发送之间插入人工事件，验证脚本、文件设置、拖放及浏览器 API 最终发送边界，并防止超时处理器的晚到操作继续执行。

下载一旦得到完成凭据，清理所有权随返回值交给 Daemon；后续人工接管不能丢弃这个凭据而遗留文件。下载编号已唯一归属当前动作后，普通人工操作只撤销后续输入，下载继续在原有截止时间内收取凭据；不能因为人工让路提前撤销监听，导致迟到文件失去归属。明确停止任务、关闭标签页或取消命令仍通过独立取消信号退出；已发出但 Chrome 尚未分配编号的请求不能保证撤回，未知结果必须核对，不能自动重试。设备模拟用现有调试连接标识保存连续配置，录屏与长截图复用同一底层图像流，避免每次动作的保护层分裂已有资源。

首次后台文件触发还须在有界面的浏览器中验证（`BSK_COOP_HEADFUL=1 BSK_COOP_COMPAT_ONLY=1`；完整前台兼容与长截图检查使用默认无头运行）：先遮住空白任务标签或最小化任务窗口，再导航到全新页面。CLI、DSH 分别以上传和下载作为该页面第一次原生点击；禁止先截图、激活任务页或重试点击来预热。检查原生事件只有一组、上传字节和下载文件一致、服务端请求次数准确，以及前台无关页面不受影响。相同场景还验证运行中只切换标签/窗口可继续、实际修改任务页会打断、清理后观察并纠正目标。

文件触发与普通点击共用 `withInputReady`：仅在隐藏页面临时准备渲染，确认渲染帧后重新测量目标并发送一次输入；最小化窗口不依赖可能永不返回的合成画面截图，随后归还临时焦点。上传和下载共用文件触发器的取消及资源清理；即使原生按下的回包迟到，也须在事务结束前释放拥有的鼠标、焦点及遮罩。单元测试控制渲染/输入回包的时序，覆盖准备失败、超时、人工打断和迟到回包，禁止旧点击继续或重复清理下一次操作的资源。

后台下载回归同时覆盖同源与跨源附件。跨源响应先发送一个字节并暂停，确保下载事件晚于临时焦点清理回执的旧超时边界；保持监听直到实际下载完成。点击准备、焦点释放及文件完成分别持有各自的生命周期，避免用点击清理的超时提前终结整个下载。

人工输入若先于下载归属确认，结果保守标记为 unknown；随后出现的下载可能属于用户，不能归入旧动作、改写路径或取消。已经唯一归属的下载则保留回执，之后仍须重新观察才能发出新动作。

### 控制提示与标签页切换

关闭控制提示只隐藏协作控件和 Agent 目标标记，不停止输入采集、让路、旧上下文失效或自动交回。保存偏好、实时开关和 UI 重新挂载复用同一显示门控；求助、借用确认和录制界面仍按原规则显示，录制结束后的隐藏状态也保持。

新建、选择、借用和归还标签页在实际浏览器变更前重新核对整个任务窗口的控制权，包含异步查询、借用确认及归还备用窗口期间的人工输入。已完成移动的借用事务仍可回滚自己的资源；显式会话停止继续走原有清理路径。
