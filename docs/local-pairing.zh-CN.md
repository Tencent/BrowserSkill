# 为什么建议本机配对？

本机配对是可选的。新安装、老用户升级、只升级 CLI 或只升级扩展，都可以继续使用未配对连接。扩展显示“已连接 · 未配对”，提醒连接身份尚未验证；不会因此禁用功能，也没有强制迁移期限。

## 配对解决什么问题

本机连接也需要区分连接方的身份。未配对时，恶意本机程序可能冒充 bsk 或浏览器连接方。配对让双方在开始浏览器操作前证明身份，降低这类冒充风险。

配对不等于系统绝对安全：它不能防御可以读取浏览器配置或 bsk 凭据文件的程序，也不会加密后续所有本机流量。未配对仍保留原有的身份冒充风险。详细协议边界见[英文指南](local-pairing.md#compatibility-and-security-boundaries)。

## 如何配对

1. 在运行 Agent 的同一套 `BSK_HOME` 下执行 `bsk daemon pair`。命令会复用或启动本机 daemon；宿主设置了 `BSK_AUTO_START=0` 时，先通过宿主启动 daemon。
2. 打开扩展的“连接设置”，把输出的完整链接粘贴到“配对链接”，点击保存。
3. 显示“已连接 · 已验证”后完成。正常重启和升级会保留配对，不需要每次任务重复操作。

链接包含一次性凭据，未使用时五分钟过期，请勿公开。如果主动配对时提示版本不支持，升级对应的 CLI／正在运行的 daemon 或扩展再试；普通未配对使用不要求同步升级两端。

尝试配对使用独立连接。链接过期或被拒绝时，原连接保持可用；配对成功后切换到验证连接。不同浏览器配置、不同 `BSK_HOME` 分别配对。

## 已配对后验证失败

已经配对的浏览器不会因为对方声称是旧版本、配对记录被重置或验证失败而自动退回未验证连接。先确认连接的是预期的 bsk，运行 `bsk doctor` 检查；需要替换配对时使用 `bsk daemon pair --replace BROWSER_ID`。

待恢复的配对也需要验证：本机保存的候选密钥可能已在 daemon 生效，不能因等待时间较长而丢弃。
如果首次配对在提交前中断、原链接已经过期，可以粘贴同一个 daemon 生成的新链接。
扩展会保留之前的候选密钥，直到新配对提交。若 daemon 提示 `already_paired`，
可重试原链接以恢复候选密钥，也可以显式生成替换链接。

## 是否需要强制所有连接配对

默认不强制。配对一个浏览器也不会要求其他未配对浏览器同步迁移。

希望自行启用严格模式时，运行 `bsk daemon trust-local off`，daemon 会拒绝未配对连接。高级设置中的“跳过本机验证”和 `bsk daemon trust-local on` 是主动绕过验证的选项，不能由程序在验证失败后自动开启。

远程连接的配对要求不受这个本机可选策略影响。
